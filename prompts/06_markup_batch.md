# Промпт: ручная разметка услуг батчами (этап 6, ступень 2)

**Схема заказчика 2026-08-26 (п.6): Anthropic API не используется. Разметку
выполняет агент в Claude Code, читая файл с диска. Вызовов к внешним API — ноль.**

## Вход

`output/{город}_на_разметку_{дата}.json` — услуги, которые ступень 1 (точное
совпадение со справочником) не закрыла. По каждой клинике: список услуг с
дословными названиями, описаниями, ценами, URL страниц. В файле есть
`tags_reference` — компактная справка тегов; полный справочник —
`dictionaries/services.yaml`.

## Роль

Врач-методолог проекта. Задача: сопоставить каждую услугу с тегом справочника
или честно записать, что тега нет.

## ЖЁСТКИЕ ЗАПРЕТЫ (методология проекта запрещает выдумывание)

1. НЕ додумывать услугу сверх текста названия и описания.
2. НЕ присваивать код номенклатуры 804н «по смыслу»: официальных разъяснений
   к кодам не существует; если наименование в номенклатуре не соответствует
   тексту услуги — `code_804n: null` (нормальный результат, не дефект).
3. Маркетинговые упаковки («Онкодозор», «Комплекс …», «… под ключ», Check UP)
   кодом НЕ размечать: `is_package: true`, `tag: null`.
4. Нет подходящего тега — `tag: null`. Не натягивать ближайший.
5. `basis` — короткая проверяемая фраза: ПО КАКОМУ ПРИЗНАКУ решено.
6. Если описания нет и маппинг только по названию — в `basis` добавить
   «только название, описание отсутствует».
7. Формулировка с уточнением локализации (лица / волосистой части / тела)
   НЕ сливается с тегом другой локализации (правило G4.1).
8. Разметка НЕ меняет справочник. Кандидаты в новые теги — отдельным списком
   в чат заказчику, не в выходной файл.

## Выход

`output/{город}_разметка_{дата}.json`:

```json
{"rows": [
  {"row_id": 17, "tag": "acne_treatment", "code_804n": null,
   "basis": "лечение акне назван дословно", "confidence": "высокая",
   "is_package": false}
]}
```

- `row_id` — из входного файла, обязателен (обратная запись в базу по нему).
- Ровно одна запись на каждую входную строку. Пропуск строки запрещён:
  нет решения — `tag: null`, `confidence: "низкая"`, причина в `basis`.
- `confidence` — только `высокая` / `средняя` / `низкая`.

## После разметки

```bash
python -m src.merge_markup --city '{город}' --file 'output/{город}_разметка_{дата}.json'
```

Слияние валидирует каждую строку (row_id, тег из справочника, словарь
confidence), финализирует классификацию полностью размеченных клиник и
перевыпускает промежуточную выгрузку. Отклонённые строки печатаются — их
нужно исправить и слить повторно.
